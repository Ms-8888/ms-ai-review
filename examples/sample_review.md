**[CRITICAL] Line 15 — Timing attack vulnerability**
`token == stored_token` uses non-constant-time string comparison. An attacker can measure response times to infer the correct token one byte at a time.
**Fix:** Use `hmac.compare_digest(token, stored_token)` which compares in constant time.

**[CRITICAL] Line 19 — SHA-256 is not suitable for password hashing**
SHA-256 is a fast general-purpose hash. GPUs can compute billions of SHA-256 hashes per second, making brute-force attacks trivial.
**Fix:** Use `bcrypt.hashpw(password.encode(), bcrypt.gensalt())` or `argon2-cffi` for password hashing.

**[CRITICAL] Line 24 — SQL injection via string formatting**
`f"SELECT * FROM users WHERE id = {user_id}"` inserts user input directly into the query. An attacker can pass `1; DROP TABLE users; --` to execute arbitrary SQL.
**Fix:** Use a parameterized query: `cursor.execute("SELECT * FROM users WHERE id = ?", (user_id,))`
